# 批量皮肤契约迁移（batch skin-contract migration）

## 何时用

- 有 **N 个（≥10）零依赖单文件 HTML 应用**，皮肤各自为政、色彩不统一。
- 用户说「把全站皮肤统一成赛博朋克 / 暗色 / X 风」「页面太丑统一一下」。
- 出现「换肤/主题功能不生效」——尤其 **只有部分页面生效**。

## 北极星

**产出「可幂等重跑的迁移器 + 契约守卫」，不是手动改一遍 N 个文件。**
手工改一遍 = 下次新增第 N+1 个应用时立刻回退；迁移器 + 守卫 = 一次性收敛且不会退化。

---

## Phase 0 · 侦察（决定方案能不能成立，别跳）

> 这一步的结论往往会**推翻原有认知**。R90 实测：记忆中「沿用原变量名就保住了换肤能力」是**错的**。

1. **盘点**：列出所有应用，产出「规模 / `:root` 有无 / `<style>` 块数 / 标题」表。
2. **算改造面**：统计每个应用的 `var(--*)` 引用数 vs 硬编码 hex 数。
   - `var()` 引用多（40+）、硬编码少（10-30，且多在 `:root` 定义本身）→ **只改 `:root` 值即可**，方案成立。
   - 硬编码 hex 铺满全文 → 改 `:root` 无效，需要逐处替换，**先评估再承诺**。
3. **找契约真源**：搜索项目里「主题/皮肤」相关页面（如 `theme-studio`），提取它写出的变量名集合。
   ```js
   // 典型：themeToCssVars() 返回的映射就是全站契约
   {bg:"--bg", card:"--card", card2:"--card2", txt:"--txt", sub:"--sub",
    line:"--line", accent:"--accent", accent2:"--accent2", up:"--up", down:"--down"}
   ```
4. **验证换肤链路是否真的通**（关键！）：
   搜所有应用里 `localStorage.getItem("theme_config")` / `theme_config` 的出现次数。
   **只出现在"主题设置页"自己 → 其余应用全都不读 → 换肤对它们完全失效**（静默失败：页面照跑、测试照绿）。
5. **给变量命名分组**（决定桥接量）：按 `:root` 里出现的变量集合聚类，典型会分出 3-5 套命名分支。
6. **标出不能碰的对象**：查项目硬规则 / 门禁。典型雷区：
   - 「某文件不得提交」（门禁会校验工作树干净）→ **必须加入跳过名单**。
   - 超大文件（1MB+）→ 先单独 dry-run 评估增量。
   - 契约真源页面本身（改它的 `:root` 可以，改它的预设数据集要慎重）。

**先跑一遍基线门禁**，确认改造前是绿的。否则改完出问题分不清是谁的锅。

## Phase 1 · 写幂等迁移器

**硬性设计约束（每一条都是踩过的坑）：**

| 约束 | 原因 |
|---|---|
| **哨兵块** `BEGIN/END` 包裹注入内容 | 幂等的前提。重复运行是「替换」不是「追加」 |
| **只追加不重排** | 保留原设计意图，降低误伤面 |
| **旧变量名就地改写为 `var(--契约)`** | 见下方「最大的坑」 |
| **删除哨兵块时连带吞掉相邻换行** | 否则每跑一次 +1~3 字符，幂等永远收敛不了 |
| **跳过名单可配置** | 硬规则文件必须排除，否则门禁必挂 |
| **`--dry-run` / `--apps` / `--all` / `--revert`** | 预检、灰度、全量、回滚 |

### ⚠ 最大的坑：旧变量名必须「就地桥接」

假设原 `:root` 里有 `--panel:#1a1a2e`，而契约里叫 `--card`。

**错误做法**：只在注入块里追加 `--panel:var(--card)`。
→ 功能上对（CSS 后声明的胜），但**原块里的裸值声明还留着**，导致：
- 守卫**无法区分「已桥接」与「漏改」**（扫到裸值就报错）；
- 留下两处冲突定义，后续维护者看到会困惑。

**正确做法**：把原 `:root` 内的 `--panel:#1a1a2e` **就地改写成** `--panel:var(--card)`。
只处理 `:root` 块内，别碰其他选择器。

### 配色：遵守 70-20-10，注意 accent2 的语义位

- 主色占比 70%，次级 20%，点缀 10%。
- **`accent2` 常被当作「渐变终点 / 次级强调」使用** → 给它一个**同色系、低调**的颜色。
  R90 踩坑：`accent2` 一开始给了品红 `#ff2e97`，结果「添加」这类按钮变成青→品红强渐变，**强调色压过主色**，违反 70-20-10。改成紫罗兰 `#7c4dff` 才对。
- 高饱和的「点缀色」留给扩展令牌（如 `--neon-magenta`）按需取用，不要塞进契约变量。

### 换肤桥接 JS

给每个应用注入最小脚本：读 `localStorage.theme_config` → 写入 `:root` 覆盖层 + 监听 `storage` 事件。
- 零依赖（内联 `<script>`，不能有 `src`）。
- 无 `theme_config` 时**不创建任何节点**（保持 DOM 干净）。

## Phase 2 · Pilot 3 个 + 真机验证

从**不同命名分支**各挑 1 个代表（覆盖最全），跑迁移 → 单测 → **真机视觉验证**。

**验证三件套（缺一不可）：**

1. **单测护栏**：每个应用若有 `test/run.js`，改完必跑，确认功能没砸。
2. **计算样式取证**（证明"皮肤真的生效"）：
   ```
   getComputedStyle(documentElement) → 取全部令牌值
   getComputedStyle(body).backgroundColor → 取实渲染值
   ```
   **只有后者能证明渲染生效**——变量有值 ≠ 页面变色。
3. **截图人工核对**：重点看**语义色有没有被破坏**（涨跌色、风险等级色、状态色）。

> CDP 零依赖脚本要点见本 skill 末尾「附：CDP 取证」。

## Phase 3 · 批量 + 门禁

1. 全量 `--dry-run` 预检，确认无 `SKIP no :root`、跳过名单正确。
2. 全量执行 → **跑全量门禁**。
3. **把「契约成立」固化成门禁项**（否则下一个人/下一次改版立刻回退）：
   - 每个应用 `:root` 必须定义全部契约变量；
   - 旧变量名若存在定义，必须是 `var(--契约)` 形式（不是裸值）；
   - 桥接 JS 在位；
   - 零依赖不变式未被破坏（无 `<script src>` / `iframe` / `url(http...)`）。
4. 提交流程：确认暂存清单**无跳过名单文件混入**（用 `git diff --cached --name-only` 核）。

## 复发防线

这类问题的本质是**「契约靠自觉，改版即回退」**，所以：

- **门禁守卫是必须项**，不是加分项。没有守卫的皮肤统一，下次改版必然静默回退。
- 守卫报错时，**先判断是「真缺陷」还是「守卫太严」**。
  R90 首轮守卫报 107 项 = 守卫正确地抓到了「旧名未桥接」，是**真缺陷**，改迁移器修掉；
  而不是去放宽守卫。
- 同时留意**偶发环境抖动**：门禁里的网络/后端项可能偶发失败（如「连接失败」断点）。
  判据：**报错的 app 是否包含「未被改动」的对象** → 若是，多半与本次改动无关，重跑确认。

## 附：CDP 零依赖取证（真机验证）

不装任何 npm 包，Node 原生起 Chrome + 自实现 WebSocket 帧编解码。

**踩坑清单：**

| 坑 | 现象 | 解 |
|---|---|---|
| `--window-size=390` | 布局视口被钳到 ~500px，截图按 390 裁 → 看着像内容被切 | **伪影，不是 bug**。真移动端必须用 `Emulation.setDeviceMetricsOverride` |
| `captureScreenshot` + `captureBeyondViewport:true` | 在 `headless=new` + 设备模拟下**静默失败**（无报错无文件） | 改用 `{format:"png"}` |
| bash `$TEMP` 传参 | Node 收到字面量字符串，路径无效 → 落盘失败 | 一律用**显式绝对路径** |
| `reg.exe` 查 Chrome 路径 | 被安全策略黑名单拦截 | `os.path.isfile` 直接试已知安装路径 |

**探测表达式**（一次性拿全）：

```js
(function(){
  var cs = getComputedStyle(document.documentElement);
  var body = getComputedStyle(document.body);
  return JSON.stringify({
    vars: {/* 逐个 pick 契约令牌 */},
    bodyBg: body.backgroundColor,      // 证明真的生效
    bodyColor: body.color,
    scrollW: document.documentElement.scrollWidth,
    innerW: window.innerWidth,         // 差值 = 横向溢出
    scriptN: document.querySelectorAll("script[src]").length,
    iframeN: document.querySelectorAll("iframe,object,embed").length
  });
})()
```
