# 对话精华提炼 → 交接文档（Handoff Doc）

本 skill 把一次对话里**真正值得长期保留**的内容，从闲聊中剥离出来，整理成一份干净的
**交接 / 知识文档**，落到工作区。之后换账号、换会话、换人都可凭这份文档接手。

核心两步：**整理 → 产出文档**。上传到云端网盘 / 知识库那一步由用户自己来（WorkBuddy 云端网盘、IMA、或其他），
skill 不负责上传，只负责把文档生成好、把路径告诉你。

## 何时使用
- 用户说"整理交接文档""导出知识资产""提炼对话精华""把这次对话存下来""做个总结存档"。
- 一段较长对话结束、或要换人 / 换账号接手时。
- 用户显式要求把某些结论沉淀成可复用文档。

## 第 1 步：整理（提炼对话精华）
通读当前对话，**只保留**以下高价值信息，剔除寒暄、试错过程、重复内容：
- 关键**结论**（最终确定是什么）
- 重要**决策**及其**理由**（为什么选 A 不选 B）
- **代码 / 配置 / 命令**片段（关键的、可复用的部分）
- 长期有效的**规则与约定**（命名、禁止操作、流程约束等）
- **待办 / 下一步**（明确的后续动作）
- 当前**进度状态**（做到哪了、卡在哪）

> 原则：宁可少、必须准。一份满是废话的交接文档比没有更糟。

## 第 2 步：产出文档（落地为 .md）
在工作区根目录（或用户指定位置）生成一份结构化文档，文件名建议
`Handoff-<项目或主题>-<YYYYMMDD>.md`。模板：

```markdown
# 工作交接 / 知识提炼文档
- 生成时间：<YYYY-MM-DD HH:MM>
- 来源：<项目 / 会话背景>
- 同步目标：<用户打算存到的地方，如「WorkBuddy 云端网盘 / IMA 知识库 XXX」，可留空>

## 1. 背景与目标
<一段话说明这次对话在做什么、要达成什么>

## 2. 关键结论
- <结论 1>
- <结论 2>

## 3. 重要决策与理由
- 决策：<做了什么选择> ｜ 理由：<为什么>

## 4. 关键代码 / 配置 / 命令
（只贴必要片段，过长可贴路径并说明位置）
` `<lang>
<片段>
` `

## 5. 规则与约定（长期有效）
- <规则 1>
- <规则 2>

## 6. 待办 / 下一步
- [ ] <动作>

## 7. 给接手方（人或新 AI）的继续指引
<说明这份文档同步到哪儿了、怎么打开、接手时该从哪一步继续>
```

如果对话里已有现成产物（报告、README、代码文件等），**不要重复搬运**——在文档里
用相对路径引用它们即可（如 `见 ./README.md`、`见 ./src/raft/raft.go`）。

## 第 3 步：交付与同步提示（不负责上传）
- 文档已落到工作区后，把**绝对路径**明确告诉用户。
- 提醒用户自行把文件同步到他选的位置（WorkBuddy 云端网盘 / IMA 知识库 / 其他）。
  这一步**由用户完成**，skill 不调用任何上传工具。
- 若用户在 WorkBuddy 里同步到了 IMA 等知识库，后续接手方可用对应入口（`@` 知识库等）读取。

> 安全边界：**不要**把密钥、token、个人隐私等敏感信息写进交接文档。
> 若对话里出现过，整理时脱敏或标注「需手动补充，勿外传」。

## 跨账号 / 跨机器可用性
- 本 skill 文件本身存在 `~/.workbuddy/skills/handoff-doc/`，只跟**当前账号 / 机器**走。
  换到没有这个 skill 的账号时，把该文件夹拷过去（或同步 `.workbuddy`）即可。
- 文档一旦被用户同步到云端网盘 / 知识库，就与机器无关，新账号可直接读取接手。

## 自检清单（生成后核对）
- [ ] 文档只含高价值信息，无闲聊与试错噪声
- [ ] 关键结论 / 决策 / 规则齐全且准确
- [ ] 无密钥、token 等敏感信息外泄
- [ ] 文件已落到工作区，路径正确并已告知用户
- [ ] 已提醒用户自行同步到所选位置（不代上传）
